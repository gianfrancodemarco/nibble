User guide

Everything you do with nibble, from asking to answering. The short version: your agent runs nibble; you just read, poke and reply.

⚠ nibble is pre-release — v0.1 is in progress. This guide describes the designed behaviour and is kept current as pieces ship; anything not yet real is marked. There is no installer yet; follow the roadmap.

01

Getting started ships with v0.1

One install, then your agent does the rest:

$ curl -fsSL https://nibble.dev/install | sh    # or: brew install gianfrancodemarco/tap/nibble
$ nibble setup                                   # installs the skill into Claude Code / Codex / Cursor

setup teaches each agent it finds when to reach for nibble and how to write good plates. After that you never type nibble commands yourself — you just talk to your agent:

"review PR #1247"

The #1 use case. Big PRs are proposed as chapters first; you agree before the first plate.

"walk me through one checkout request, end to end"

System parts, request flows — a map and a sequence, the code at every stop.

"walk me through what you just changed"

The uncommitted diff as a map coloured by churn, one compare per claim.

02

A plate arrives

A plate is one explanation: up to ~7 nibbles, each one claim with one visual and the code behind it. How it reaches you follows one rule — the human holds the pen:

You asked for it

It opens itself. You were waiting for it; no extra click.

The agent volunteered it

It waits in the pill (menu-bar icon, v1) until you open it. It never steals focus. v0.1: browser tab

It's still being written

Open it anyway — nibbles stream in live while the agent works.

03

Reading a plate

The canvas takes most of the window; the caption sits below it; code lives in a drawer. Moving between nibbles glides the camera across one shared map, so you build a spatial picture as you go. Try the live mockup.

Keys

keydoes
← →previous / next nibble (camera move, not a page swap)
spaceplay / step the active visual
eopen the evidence drawer (the code behind the selection)
ccomment on the selected thing
vrequest a missing visual from the selected thing v0.2
wvoice walk: captions read aloud, highlight in sync v0.2
ssubmit your review
qclose without answering

What each visual lets you do

map

Click a node → its code in the drawer. Highlight a path. Collapse a group.

sequence

Step message by message; branches (alt) show where it could have gone.

timeline

Scrub time. Toggle precomputed states — "jitter off / on" — and compare.

compare

Flip or slide between before and after: code, a map, or metrics.

The detail dial

Every plate reads at three depths on the same canvas: overview (the shape, one sentence — enough to decide whether to care), standard (what a plate opens at), deep (per-element numbers and edge cases, generated on demand v0.2). A ninety-second review and a ten-minute one are the same plate.

Trust badges

Code moves while plates sit. Every ref re-checks against the file as it is now:

exact

The lines are exactly where the agent said.

shifted +3

Same lines, found whole at one new position; the offset is shown.

stale

Rewritten, gone, or ambiguous. nibble never guesses — stale means go look.

04

Answering

Disagree on the thing itself: select a node, an edge, a moment on the timeline or lines in the drawer, and press c. Two ways to send it:

Ask now

Ends the agent's wait immediately with your question. The answer comes back threaded into the same plate.

Hold for review

Keeps the comment until you press s and choose a verdict: approve, changes, or discuss.

In a PR review, check the end of the plate before approving: the not-shown ledger lists every hunk of the diff no nibble referenced, and the map badges dependents the plate never visited — callers, tests, configs of changed code. That's where agent-written PRs go wrong, and both are open to comments like anything else.

05

For agents (and the curious)

Everything above rides on four commands and a folder of plain JSON. The full contract — formats, the ref grammar, fingerprint and trust rules, every error code — is PROTOCOL.md, with golden fixtures as its executable conformance suite.

$ nibble new   --title "PR 1247 · ch 1: payments" --about pr:1247   # prints the plate path
$ nibble add   <plate> --caption "…" --visual timeline.json \
               --ref "src/cache/prices.ts:43-45 @cache"
✗ rejected: src/cache/prices.ts has 41 lines, ref ends at 45      # validation is strict, errors are fix-its
$ nibble done  <plate>                                              # seals it; coverage gaps reported
$ nibble serve <plate>                                              # blocks; exits with your review

Worth knowing:

Plates live in ~/.nibble/plates

Keyed by repo and commit; your repos stay clean. nibble export copies one into a repo to share it.

Budgets, not walls

~5 nibbles for a bug, maybe 12 for a PR chapter. Going over needs --because, and the reason is printed on the plate for you to judge.

No pixels

Agents declare what things are — plus semantic hints (group, tier, focus). nibble draws everything, so the same idea always looks the same.
