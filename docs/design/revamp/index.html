Reader revamp: what broke, what I fixed, three ways forward

I drove the shipped reader with a headless browser over four plates (a sealed five-nibble plate, one with a conversation, one whose repo is missing, one still being written) and measured the camera after every move. Six navigation bugs reproduced; they are fixed in the working tree. The three variants are live pages you can read, poke and compare. Each fixes the same bugs by construction and proposes a different shape for the reader.

Three directions

AFilmstrip chosen

The shipped layout, kept, with the camera handed to the browser: a native horizontally scrolling strip with snap points. Neighbours peek at both edges and are clickable, the rail is numbered and badged, the help is a popover. No transform math left to go wrong.

New: a fullscreen mode for the visual. Press f, the ⤢ on the visual, or double-click it: the picture fills the window with the claim as a caption, arrows keep stepping, chips open the code as a sheet, esc hands it back.

For: the smallest change that keeps the spec's one canvas and camera. Trackpad, wheel, click, keys and buttons all work the same way.

BReading column

The plate as a document you scroll down. One card per screen, the claim as a header band over a full-width visual, and a table of contents on the left that doubles as progress and message map. Arrivals append at the bottom like any feed.

For: long plates, reviewers who skim, the streaming case. Costs the "camera glides across a strip" idea; gains a layout every reader already knows.

CStage

One picture fills the window; the claim sits under it as a caption; a chapter bar at the bottom is the only navigation. Code and chat are sheets that slide over the stage, so the picture never changes size. The move between nibbles is a crossfade, not a strip.

For: "picture first, prose last", literally. Retired: A's fullscreen mode takes this idea without giving up the strip.

How to read them

Each variant is the same plate with the same five visuals, the same two threads and real code behind the chips. Try the arrow keys, a trackpad swipe, the number buttons, ⎵ on the sequence and the timeline, a chip, d, ?, c, and t for the dark theme. Pick one, or name the parts you want from each; the OpenSpec change reader-ux-revamp carries the decision and the tasks.
