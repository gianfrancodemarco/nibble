Reading a plate

The canvas takes most of the window. The title sits below it — with its description when the nibble has one — and the code lives in a drawer. Moving between nibbles moves the camera across one shared map. You can try the live demo below: it is the real reader on a real plate.

Keys

keydoes
← →previous / next nibble (camera move, not a page swap)
spaceplay / step the active visual (step a sequence, jump the timeline cursor, flip a compare; shift reverses)
ddetail dial: flip every visual between overview and standard (deep arrives in v0.2)
eopen the evidence drawer (the code behind the selection)
ccomment on the selected thing
vrequest a missing visual from the selected thing v0.2
wvoice walk: titles read aloud, highlight in sync v0.2
ssubmit your review
qclose without answering

In the v0.1 reader, ← →, space, d (the dial), ⏎ (pin comment), s (send, once a verdict is chosen), esc (drawer, then selection) and ? (the in-reader legend) are live. Clicking does the rest: selecting an element pins comments to it (n2:cache), and its </> chip or any ref opens the code drawer.

The visuals

Each visual renders as interactive SVG. The reader lays it out from what the agent declared: the agent sends the meaning, the reader draws the pixels.

map

Click a node: it and its edges highlight, the rest dims. Its </> chip opens the code in the drawer.

sequence

Step message by message (space or click a step). Branches (alt) show where it could have gone.

timeline

Scrub time: events ahead of the cursor fade to pending. You can toggle precomputed states, for example "jitter off / on".

compare

Flip between before and after: code (with its trust badge), a map, or metrics aligned to read across.

The blast radius

A PR plate usually opens with a ringed map: the whole change in three concentric zones, read inside-out. The centre is what changed. Around it sit the dependents — files that did not change but depend on something that did: callers, importers, tests, configs, grouped by why they depend. Outside is the rest, kept for orientation. The agent computes the rings from the repo; nibble only checks they are complete and draws them.

The dependents ring is the review's checklist. Every dependent you haven't looked at carries a badge, and the ring's label counts them — 3 of 5 unvisited — ticking down as you select a node or open its code, until it reads done. The count lives in this tab only: it never enters your review, and nothing is sent about what you did or didn't open. It exists so you don't approve a PR with a caller you never glanced at.

The not-shown ledger

A plate about a diff ends with one more card: the ledger — every hunk of the diff that no nibble referenced, grouped by file with its side and line counts. It is written when the plate is sealed, computed by nibble from git, never by the agent — so the walkthrough cannot quietly skip anything. Click a hunk to read those exact lines in the drawer (removed code is shown as it was on the base side), and comment on a hunk or on the ledger as a whole like anything else; those comments reach the agent as ledger:path:lines targets. A fully covered diff still shows the card, saying so. Check it before you approve: it is the part of the diff nobody walked you through.

The detail dial

Every plate reads at three depths on the same canvas: overview (the shape in one sentence, enough to decide whether to care), standard (what a plate opens at), deep (per-element numbers and edge cases, generated on demand v0.2). You can spend ninety seconds or ten minutes on the same plate.

In the v0.1 reader the dial has two positions — press d (or use the toggle next to the stepper) to flip between overview and standard. Nothing moves when you turn it: the overview is the same picture drawing less, so what you located at a skim is exactly where it stays when you go deeper. If the element you had selected isn’t drawn at overview, the selection clears and comments fall back to the whole nibble. Prose follows the dial too: the plate and each nibble can carry a two-depth description under their title — the skim text at overview, the fuller story at standard.

Trust badges

The code keeps changing after a plate is written. For this reason, every ref is re-checked against the file as it is now.

Checking degrades per ref, depending on what this machine has. A plain ref and a @worktree ref only need their file. A base..head ref needs git. With the plate’s repo present, everything is verified. With just a folder of files, only base..head refs fall back to unverified. With nothing, the plate still opens with text and visuals, but every ref is unverified. The review loop works in all three cases.

exact

The lines are exactly where the agent said.

shifted +3

The same lines were found whole at one new position. The offset is shown.

stale

The lines were rewritten, are gone, or are ambiguous. nibble never guesses: stale means you should go look.

unverified

nibble couldn’t check: the plate’s repo isn’t on this machine, or a base..head ref has no git. This is different from stale, because nothing is known either way.
