Getting started

This guide covers everything you do with nibble. Your agent runs the nibble commands. You just read, poke and reply.

⚠ nibble is pre-release: v0.1 is in progress. This guide describes the designed behaviour and is updated as features are released. Anything not implemented yet is marked. There is no installer yet; follow the roadmap.

Install installer comes with v0.1

The CLI already works. For now, you have to build it from source:

$ go install github.com/gianfrancodemarco/nibble/cli/cmd/nibble@main

The brew tap and the skill setup are not published yet:

$ brew install gianfrancodemarco/tap/nibble      # tap not published yet
$ nibble setup                                   # installs the skill into Claude Code / Codex / Cursor

setup installs the skill into each agent it finds. The skill tells the agent when to use nibble and how to write good plates. After that, you never type nibble commands yourself.

Try it without an agent

The repository contains a real example plate (the one the test suite writes), together with a snapshot of the files it references. You can serve it directly from the checkout:

$ git clone https://github.com/gianfrancodemarco/nibble && cd nibble
$ go install -C cli ./cmd/nibble
$ nibble serve protocol/golden/plates/cli-authored/plate   # prints reader: http://127.0.0.1:…; open it

That plate is already reviewed, so it opens read-only with the verdict visible. To answer it yourself, serve an unreviewed copy:

$ tmp=$(mktemp -d) && cp -R protocol/golden/plates/cli-authored/* "$tmp" && rm "$tmp/plate/review.json"
$ nibble serve "$tmp/plate"      # comment, choose a verdict, send; serve exits with its code

What to ask

You just talk to your agent:

"review PR #1247"

The main use case. Big PRs are split into chapters first, and you agree on them before the first plate.

"walk me through one checkout request, end to end"

You get a map of the system parts and a sequence of the request, with the code at each step.

"walk me through what you just changed"

You get the uncommitted diff as a map coloured by churn, with one compare for each claim.
