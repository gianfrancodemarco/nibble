Getting started

Everything you do with nibble, from asking to answering. The short version: your agent runs nibble; you just read, poke and reply.

⚠ nibble is pre-release — v0.1 is in progress. This guide describes the designed behaviour and is kept current as pieces ship; anything not yet real is marked. There is no installer yet; follow the roadmap.

Install installer ships with v0.1

The CLI already works — today it builds from source:

$ go install github.com/gianfrancodemarco/nibble/cli/cmd/nibble@main

The brew tap and skill setup are coming:

$ brew install gianfrancodemarco/tap/nibble      # tap not published yet
$ nibble setup                                   # installs the skill into Claude Code / Codex / Cursor

setup teaches each agent it finds when to reach for nibble and how to write good plates. After that you never type nibble commands yourself.

Try it now — no agent needed

The repo ships a real example plate (the one the test suite writes), bundled with a snapshot of the files it references. Serve it straight from the checkout:

$ git clone https://github.com/gianfrancodemarco/nibble && cd nibble
$ go install -C cli ./cmd/nibble
$ nibble serve protocol/golden/plates/cli-authored/plate   # prints reader: http://127.0.0.1:… — open it

That plate ships already reviewed, so it opens read-only with the verdict visible — reading after the fact. To answer it yourself, serve an unreviewed copy:

$ tmp=$(mktemp -d) && cp -R protocol/golden/plates/cli-authored/* "$tmp" && rm "$tmp/plate/review.json"
$ nibble serve "$tmp/plate"      # comment, choose a verdict, send — serve exits with its code

What you say

You just talk to your agent:

"review PR #1247"

The #1 use case. Big PRs are proposed as chapters first; you agree before the first plate.

"walk me through one checkout request, end to end"

System parts, request flows — a map and a sequence, the code at every stop.

"walk me through what you just changed"

The uncommitted diff as a map coloured by churn, one compare per claim.
