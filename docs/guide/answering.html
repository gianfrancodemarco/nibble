Answering

The plate has a chat, fixed on the right beside the nibble you are reading: every conversation on the plate, each pinned to the thing it is about — a node, a step, a moment on the timeline, a file in the ledger, or a whole nibble.

Select something and write. Your message appears at once as a draft bubble under a thread headed by its target (n2:cache), and the composer says where it will go: a new thread on the selection, or a reply in a thread that already exists there. Drafts can be removed. Nothing has been sent yet.

Send ⌘⏎

Sends this message and every held draft at once, as one round. The agent wakes immediately.

Hold ⇧⌘⏎

Keeps the message as a draft. Write as many as you like, on as many things as you like — they go out with the next send.

Send is the one deliberate action. Only it ends the agent's wait; a round is what you send, posted together. There is no done button: when you have nothing more to say, say nothing — the agent moves on when its wait times out, and the page stays up for whenever you come back.

The loop

After you send, the agent is awake and the panel locks: sent — the agent is answering · 0 of 2. Leave the tab open. The agent reads the round as a batch, makes any change you asked for in the code, and answers each message on the plate, pinned under your message, with the lines that prove it: a reply bubble with code chips you can open in the drawer, and phrases that light up the picture when you hover them. Replies land one by one; the count ticks up. When every message has one, the panel unlocks: your turn — reply, or write elsewhere.

Then it is your turn again. Reply inside a thread to keep the conversation on that thing, open a new thread elsewhere, or say nothing when there is nothing to address: the agent moves on, the page stays up, and you can write again later. Elements and cards with a conversation wear a small count badge; click it to jump to that thread, and click a thread's target chip to jump back to the thing on the plate.

The page stays up the whole time: when the agent's wait ends, a keeper takes over serving the plate, and the agent's next wait takes it back, so the tab never needs a new link. The chat's header carries the message count and a live marker while the agent answers; c puts the cursor in the composer.

In a PR review, check the end of the plate before you answer. The not-shown ledger lists every hunk of the diff no nibble referenced — each opens its code in the drawer — and the map badges dependents the plate never visited (callers, tests, configs of the changed code). That's where agent-written PRs usually go wrong. Both take threads like anything else.

Messages travel back pinned to what you selected, each carrying its trust level, so the agent knows exactly what you meant even if the code moved.
